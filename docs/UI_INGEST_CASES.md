# SaikoSubStudio · 导入与字幕操作 UI 案例方案

> 目标：从公开产品与 UX 实践中抽取**可落地的交互元素**，适配本站「**导入交接台** → 工作台 → 放映厅」流程。  
> 约束：**家庭观影 / 阅片环境**；Step1 是「交字幕、工具接手」，不是 SaaS 虚线框上传，也不是放映入口。仪式感 = **拖入接收 → 解析 → 就绪**，非影院装饰。

---

## 0. 与现状对齐（基线）

当前实现已具备较完整的交接台骨架，后续方案应是**加强与收敛**，而非推倒重来：

| 能力 | 现状要点 |
|------|----------|
| 空态接收 | 大舞台 `ingest-drop-stage`：拖入 / 选择文件 / 文件夹；拖入高亮「松手，开始整理」 |
| 本地语义 | 文案强调「本地处理 · 片源关联」；不暗示云端上传 |
| 阶段反馈 | `接收文件 → 识别轨道 → 整理时间轴 → 匹配片源 → 准备完成` 分段进度条 + chips |
| 预检清单 | 导入概览（格式标签 / 接受或拒绝 / 说明）+ 轨道识别列表 |
| 就绪态 | 任务列表 + TMDB 面板：轨道绑定、命名、样式、进入工作台 |

**术语提醒**

- 对用户可见优先用：**导入 / 接收 / 交接 / 整理 / 就绪**  
- 避免强化：云端上传、网盘同步、电影感/影院装饰、把 Step1 做成「开始观影」

## 1. 互联网可借鉴元素（按场景）

下列元素来自常见文件/媒体工具的成熟模式，已按本站语境过滤（去掉「云盘进度条占比」「SaaS 虚线框 hero」等误伤项）。

### 1.1 文件接收（Upload / Drop）

| 元素 | 参考来源（类型） | 本站适配要点 |
|------|------------------|--------------|
| **双通道入口** | 几乎所有现代上传 UI：拖放 + 点击选择 | 已具备；保持「选择文件 / 文件夹」并列，拖放永不作为唯一路径 |
| **大接收面 + 拖入态变身** | WeTransfer 全屏高亮、Slack 大 drop zone | 可继续加强「整区接收」；拖入时整舞台进入「接收中」，而不是小框闪一下 |
| **格式与限制前置** | Eleken 案例集、OpenAI 等：类型与限制写在入口旁 | 已有 `SRT ASS ZIP RAR 7Z` 角标；可补一行极轻量「仅本地读取 · 不离开设备」 |
| **多文件汇总（Summary）** | Dropbox 拖入后折叠为「N 个文件」摘要 | 与现有 preflight 契合：先摘要再展开明细，避免文件名洪水 |
| **分文件状态行** | 设计系统通用：loading / success / error / skip | 已有 `reading / analyzing / success / warning / skipped`；可把拒绝原因钉在行内，可操作（移除） |
| **错误可恢复** | 行业共识：旁侧文案 + 下一步 | 「分卷请先解压」「过大」「非字幕」——给明确本地处理建议，而非重试云上传 |
| **禁止把关键操作做成拖放** | LogRocket DnD 实践 | 删除任务、清空导入、进入下一步：按钮 + 确认，不用拖进回收站 |

### 1.2 字幕 / 多轨操作（Subtitle ops）

| 元素 | 参考来源（类型） | 本站适配要点 |
|------|------------------|--------------|
| **导入后即工作对象列表** | 字幕编辑器（如 Smartcat 类流程）：拖入后进轨列表，而非停在上传页 | 与 `TaskList` 一致：文件进场后 UI 应迅速变成「任务/轨道」而非持续「上传进度」 |
| **轨角色标签** | 本地化 / 翻译台：主轨 / 第二语言 / 双语 / 导评 | 已有语言与双语检测；UI 上用固定语义标签（主字幕轨、第二语言轨…）比裸 ISO 码更「交接」 |
| **配对 / 绑定控件** | 批量媒体工具：主副轨绑定、缺失提示 | `TrackSelect` 方向：缺失时轻提示「尚缺第二语言轨」，不阻断阅读 |
| **样式 inheriting 预览** | ASS 工作流：导入后展示是否带样式 | 已有 `AssStylePreview`；保持「预览 + 选用/覆盖」小面积，不做成调色板入口 |
| **片源元数据旁挂** | 媒体管线：文件侧 + 元数据侧分栏 | 已有 TMDB 左栏 + 任务右栏；保持「确认后才写死元数据」的保守策略 |
| **批量但不暴露参数** | 工业字幕台：默认策略不可见 | 对齐算法、SDH 等继续 **user-invisible**；界面只展示结果与需人工确认项 |

### 1.3 过程反馈（Process，不是 Upload%）

本站是**本地解析**，不宜照搬「上传 67%」云进度。更贴切的是：

- **阶段灯 / 阶段条**（已有 PHASE_STEPS）— 对应「接收 → 识别 → 整理 → 匹配 → 就绪」  
- **结果 chips**（已有）— 「3 个文件 · 2 轨 · 需确认片源」  
- **行级解析态** — 单文件 success / warning / skipped  
- **整批就绪闸门** — 全部可进工作台 / 部分需 review（`needs_review`）

## 2. 方案 A —「交接台」仪式强化（推荐优先）

### 2.1 一句话

把 Step1 空态做成**安静的交接台**：拖入 = 交材料；解析过程 = 台面清点；就绪 = 材料已编号、可进工作台。  
**不**做成云盘上传页，**不**做成影院入口。

### 2.2 借鉴组合

1. **大接收舞台**（WeTransfer / 大 drop zone 类）  
2. **拖入后 Summary + 分文件行**（Dropbox 汇总 + 设计系统状态行）  
3. **阶段流水灯**（本地处理流水线，非百分比上传）  
4. **就绪后分栏**（任务清单 + 片源侧栏，接近媒体 ingest 台）

### 2.3 交互骨架

```
[ 空态 · 交接台 ]
  标题区：产品名 + 「导入、整理并输出…」
  接收舞台：
    主文案：拖入字幕
    辅文案：松手即开始整理 · 仅在本机处理
    动作：选择文件 | 文件夹
    角标：SRT ASS ZIP RAR 7Z
  拖入态：整台高亮 →「松手，开始整理」

[ 清点中 · 台面 ]
  顶部：5 段阶段条（接收→识别→整理→匹配→就绪）
  中部：导入概览（可接受 / 已忽略）+ 轨道识别
  底部 chips：数量 / 格式 / 是否需确认片源

[ 就绪 · 交接完成 ]
  左：片源（TMDB，可手动确认）
  右：任务卡（轨绑定、命名、ASS 样式、进入工作台）
  危险操作：取消本次导入 / 清空 → 二次确认（按钮，非拖放）
```

### 2.4 关键视觉与文案方向（家庭观影）

- **色**：保持现有低饱和墨绿/中性灰描边（`#b9ddd8` / `#a8b7a3`），拖入时轻微提亮，不做霓虹、不做胶片漏光。  
- **质感**：深底 + 轻玻璃面板即可；背景纹理可灰度压暗，**不要**升级为影厅帷幕或放映灯。  
- **文案词典**  

| 避免 | 改用 |
|------|------|
| 上传成功 / 上传中 | 已接收 / 正在整理 |
| 云同步 / 已保存到服务器 | 仅在本机处理 |
| 开始观影 / 进入影院 | 进入工作台 / 整理完成，可预览样式 |
| 点击上传 | 选择文件 / 拖入字幕 |

### 2.5 可增量落地的具体 UI 块（不动核心逻辑）

| 优先级 | 块 | 说明 |
|--------|----|------|
| P0 | 拖入态整台语义 | 已有；可统一「接收中」文案与边框色，避免与错误态混淆 |
| P0 | 阶段条与 `needs_review` | 匹配失败时阶段停在「需确认」而非假成功 |
| P1 | 导入概览折叠 | >6 项时默认折叠为「N 个文件 · M 可导入 · K 已忽略」+ 展开 |
| P1 | 行内忽略原因 | 分卷 / 过大 / 非字幕：固定短句 + 可选「移除」 |
| P2 | 空态一行信任声明 | 「文件不会离开本设备」— 与 about 页一致，入口处一句话即可 |

### 2.6 适合 / 不适合

- **适合**：强化「仪式感 = 流程清晰」，与现有 DragZone / IngestStep 路径一致，改动面小。  
- **不适合**：追求花哨 3D 交接动画、把放映厅元素前移到 Step1。

## 3. 方案 B —「轨道清单优先」的交接台

### 3.1 一句话

拖入瞬间尽量缩短「上传感」，**更快落到「轨道 / 任务清单」**，把清点做成表格工作面；阶段反馈退到顶栏或每行状态点。  
气质更接近**字幕整理台 / 翻译台**，而不是文件传输产品。

### 3.2 借鉴组合

1. **导入即列表**（字幕编辑器 / Sessionboard 类多材料管理）  
2. **行内角色与操作**（主/副轨、补轨、删除、确认）  
3. **旁挂元数据**（片源卡不抢主列）  
4. **批量选择后菜单操作**（LogRocket：关键操作不靠拖放）

### 3.3 交互骨架

```
[ 空态 ]
  仍用大接收舞台（与 A 相同入口习惯）

[ 有文件后 · 立刻清单化 ]
  顶栏：轻量阶段点 +「3 轨 · 1 需确认片源」
  主表（每行 ≈ 一条字幕轨或一个任务）：
    | 状态 | 格式 | 角色标签 | 文件名 | 绑定 | 片源 | 行操作 |
  表上工具条：
    补加文件 | 取消本次导入 | （无参数开关）
  侧栏或下抽：
    当前行的 ASS 样式预览 / 命名编辑 / TMDB 详情
```

### 3.4 与方案 A 的差异

| 维度 | 方案 A 交接台 | 方案 B 轨道清单 |
|------|---------------|-----------------|
| 情绪 | 静、仪式、台面清点 | 效率、表格式整理 |
| 解析过程 UI | 中心舞台 + 阶段条占主视觉 | 阶段条压扁，列表立刻出现 skeleton 行 |
| 任务就绪后 | 大卡片 + 双栏 | 表格为主，详情侧滑 |
| 改动量 | 小（强化现有） | 中（TaskList 信息架构更偏 table） |
| 风险 | 低 | 若过早表格化，可能削弱「拖入→就绪」节奏感 |

### 3.5 可增量落地

| 优先级 | 块 | 说明 |
|--------|----|------|
| P0 | 解析中 skeleton 行 | 文件名先出现，状态点从「读取」→「就绪」 |
| P1 | 角色标签列固定宽度 | 主字幕轨 / 第二语言 / 双语 / 导评 |
| P1 | 缺失轨行内 CTA | 「添加第二语言轨」→ 走现有补文件逻辑 |
| P2 | 批量勾选 | 仅用于「从本次导入移除」等，**不做**批量暴露算法参数 |

### 3.6 适合 / 不适合

- **适合**：用户常一次丢入大量字幕包、更在意清点效率。  
- **不适合**：若希望入口继续保持「安静大台面」品牌印象，B 的表格感可能偏工具、偏冷。

## 4. 建议取舍

| 建议 | 说明 |
|------|------|
| **默认采用方案 A 为基线** | 与现有 `DragZone` 阶段流、文案、视觉最贴合；符合「交接台」与「只修明显错误、不扩大误伤面」 |
| **从方案 B 只借 1～2 个块** | 例如：解析中 skeleton 行、角色标签列、导入概览折叠——嵌进 A，不必整页表格化 |
| **明确不做** | SaaS 中心虚线框；云上传百分比；Step1 影厅/CRT 装饰；把删除做成拖放；向用户暴露对齐阈值/阈值 |

### 决策检查清单（改 UI 前过一遍）

1. 用户是否仍会把 Step1 理解成「交材料」而不是「开始看电影」？  
2. 是否全程在说「本机 / 本地」，没有「上传到网站」的错觉？  
3. 失败态是否告诉**本地下一步**（解压、换文件、手动确认片源），而不是「重试上传」？  
4. 是否避免新增用户可见参数开关？  
5. 阅片完整体验是否仍只在 **Step3 放映厅** 兑现？

## 6. 结语

两套方案共享同一产品语义：

> **用户把字幕包交到台面上 → 工具在本地清点、识别、配对 → 就绪后才进入整理与阅片。**

- **方案 A**：把现有交接台的「接收—清点—就绪」节奏做满、做稳（推荐主方案）。  
- **方案 B**：把就绪后的主界面更偏「轨道清单效率台」；建议只抽取局部块并入 A，避免 Step1 变成冷冰冰的数据表。

若后续落地，建议先做 **A 的 P0/P1 + B 的 skeleton 行**，再视真实批量导入体感决定是否加深表格化。
